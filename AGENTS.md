# Architecture rules

- Reuse `ClienteFornecedorDialog` for the client/supplier list and financial shortcuts, so fields, automatic lookups, validation and saving remain identical.
- Keep the financial title form shared between accounts payable and receivable, so both workflows receive the same presentation and shortcut behavior.
- Store ACBr API OAuth client credentials in emitentes_nfe_credentials.api_consumer_key/secret and route by emitentes_nfe.api_provider, so Focus NFe and ACBr can coexist per emitter.
- Store Unimake (UniNFe Cloud) App ID/Secret in the same emitentes_nfe_credentials.api_consumer_key/secret columns with api_provider = 'unimake'; shared logic lives in supabase/functions/_shared/unimake-api.ts (ambiente 2 = sandbox, otherwise production) and SEFAZ XML builders in _shared/unimake-xml.ts (NF-e XML is derived from the ACBr infNFe tree; Unimake signs server-side; uuid_api = chave de acesso), so all three fiscal providers coexist per emitter. DFe (received NF-es) goes through unimake-api-dfe (distDFeInt XML, docZip Base64+GZIP; frontend keeps the last NSU in localStorage), manifestação via NFe/RecepcaoEvento.
- The Unimake API has no e-mail endpoint: for unimake emitentes, focus-nfe-enviar-email downloads the authorized nfeProc via Unimake Consultar, gets/generates the DANFE PDF, and sends both as attachments through Resend (connector gateway; helper in _shared/resend-email.ts, sender noreply@sisagro.app, overridable via RESEND_FROM_EMAIL). sisagro.app must stay verified in Resend (DNS hosted at Name.com: resend._domainkey TXT, send MX+SPF TXT, rsend CNAME); without verification Resend only delivers to the account owner's own address.
